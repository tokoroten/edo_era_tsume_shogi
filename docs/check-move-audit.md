# 初手の王手全列挙による監査（2026-11-25）

詰将棋は**必ず王手で始まる**。したがって「盤面上で合法な王手をすべて列挙する」ことは、
盤面の翻刻と列頭（詰手の初手）の両方に対する独立した制約になる。この監査は
`tools/check_moves.py` で機械的に再現できる。

```
python tools/check_moves.py                 # 両コレクション・? が6升以下
python tools/check_moves.py seimyo --max-q 9 --only-fail
python tools/check_moves.py --md --moves    # 全王手を Markdown 表で
```

実装上の注意（過去に誤判定を生んだ点）:

- **成駒を動かすときは成りのまま**。と金を「と→歩」に戻すと王手が消える。
- **打ち歩は二歩・死に升・打ち歩詰めを除外**。除外しないと「唯一の王手」が幻になる。
- `?` は空き升として扱うので、王手の**個数は上界**。ただし着手元・経路・着地点が
  `?` に触れない王手は、`?` が何であっても合法（表中の `solid`）。

## 集計

判定は3種類:

| 判定 | 意味 |
|---|---|
| `head-ok` | 記録された初手（駒種・行き先・成り）が合法な王手として存在する |
| `dest-ok` | 記録された**行き先**には王手になる手があるが、記録された**駒種**では届かない |
| `dest-absent` | 記録された行き先**自体**が、その盤面の王手の升ではない |

| コレクション | `?` の範囲 | head-ok | dest-ok | dest-absent |
|---|---|---|---|---|
| 精妙 | 0–4 | 58 | 6 | 18 |
| 精妙 | 5–9 | 3 | 1 | 4 |
| 精妙 | 10–14 | 0 | 0 | 2 |
| 精妙 | 15–19 | 0 | 2 | 4 |
| 精妙 | 20–24 | 0 | 0 | 2 |
| **精妙 計** | | **61** | **9** | **30** |
| 貫珠 | 0–4 | 34 | 4 | 4 |
| 貫珠 | 5–9 | 4 | 0 | 0 |
| 貫珠 | 10–14 | 0 | 0 | 1 |
| 貫珠 | 20–24 | 1 | 0 | 2 |
| **貫珠 計** | | **39** | **4** | **7** |

`?` の多い盤面（15升以上）は王手の列挙自体が信用できないため、判定は暫定。
`?` が5升以下の盤面では列挙はほぼ確定で、**そこでの不一致は盤面か列頭のどちらかが誤り**である。

## 不一致の原因は3つに分かれる

1. **駒種の誤読**（`dest-ok`、行き先は正しい）
   - 四十三番: 記録 `一八香` → 盤面では2九の銀だけが1八へ届く ⇒ `一八銀` に訂正。
   - 三十九番: 記録 `四二香` → 1四の飛だけが2四へ届く ⇒ `四二飛` に訂正。
2. **列の帰属の誤り**（`dest-absent`、行き先が王手の升でない）
   - 三十八・五十六（`?`=0 の完成盤面でさえ一致しない）ほか。
3. **盤面の誤り**（合法な王手が1つも無い）
   - 十八番: 唯一の候補 `P*8f` は**二歩**（8九に先手歩）。他に王手が無く、盤面が誤りと確定。
   - 七十五番: 合法な王手が0。盤面が誤り（または大きく欠落）。

## ソルバーによる裁定（新しい判定法）

「合法な王手だが、詰まない」列頭は、**ソルバーで反証できる**。詰将棋の初手は詰みに
至る手でなければならないので、反証された手は初手ではない。

七十二番（`?`=2）が最初の適用例:

| 手 | ソルバー | 備考 |
|---|---|---|
| 二七と（記録列頭、6三のと→7二） | 1手で反証 | 8一玉が7二のとを取る |
| **八二歩打** | **9手詰**（nodes 8,065 / exhaustive） | 採用 |

初手を `八二歩打` に差し替え、`二七と` の列は `verified: false` とした
（`docs/seimyo-transcription.md` 「七十二番: 初手のソルバー裁定」）。

この方法は `dest-ok` / `dest-absent` の残件にもそのまま使える。盤面が十分に読めていて
（`?` が少ない）、ソルバーが詰みを返せば、その初手が答えであり、列頭の食い違いは
列の帰属の問題だと確定する。逆に詰みが返らない場合は、盤面側の誤りを疑う。

## 次にやること

- `?` が5升以下で `dest-ok` / `dest-absent` の残件にソルバーを当てる
  （詰みが出れば初手確定、出なければ盤面再読）。
- 現在の残件は `docs/open-issues.json` に候補SFENつきで構造化してある。

## 成駒の比較で一度誤集計した（2026-11-25）

## なぜ候補盤面を採用できないか（データ構造上の理由）

初手レコードは盤面と対になっている:

- `docs/*-first-moves.json` の各行は 1題=1初手。
- `docs/first-move-status.md` の行集合は JSON と一致していなければならない（テスト）。
- `tests/run_tests.py::test_first_moves_check_the_king` は、初手の駒をその升に置けば
  王手になることを要求する。

したがって「盤面だけ差し替えて初手は未決」という状態を表現できない。盤面を採用すると
初手も同時に確定させる必要があり、列頭が王手の集合に入らない題では採用できない。
**列頭を `unassigned` にできるデータ構造**（例: `head_unassigned: true` と
`best_check` 候補）を先に用意するのが、残り133升を活かすための前提条件である。

## 貫珠 十八番の追試

原寸（900px）で列頭を再確認し、**一三銀成** の `銀` と `成` を読み取った（`角` ではない）。
盤面の `?` は4二の1升だけで、銀を4二に置けば 3一成 が王手になる（他に候補なし）。
しかし完成させた盤面は11手以内に詰みが無い（厳密）。列頭と盤面の両方が読めているのに
詰まないため、**どちらかを採用するには原本の手順列が必要**という結論になった。

## 解決: `head_unassigned`（2026-11-25）

上の「データ構造上の理由」は解消した。初手レコードに **`head_unassigned: true`** を
持たせ、盤面だけを採用できるようにした。

- `docs/*-first-moves.json`: 印字された列頭（`raw`/`piece`/`file`/`rank`）は残し、
  `head_unassigned: true` を付ける。`board_q`・`confidence` は盤面に合わせる。
- `tests/run_tests.py`: 王手検証・成り・打ち歩・自駒の4テストはこの印の行を飛ばす
  （代わりに `test_board_q_matches_draft` が盤面の品質を検査する）。
- `tools/head_check.py`: 状態 `UNASSIGNED` を返す。
- `docs/first-move-status.md`: 初手欄を「未決（列頭 …）」とし、件数は「検証済み 47/50・96/100」。

## 成りの列頭は「成り先」を指す（2026-11-25 の検証）

精妙九十七番の列頭 `三五角成` は、盤上の角の位置 5三 と一致するが**成り先ではない**
（5三の角は 4二/6二 へ成って王手）。そこで「成りの列頭は成る駒の位置を指す」という
仮説を全題で検査した。

- 成りを含む列頭: 精妙21・貫珠8。
- 仮説に合う（印字2字が、成って王手になる未成り駒の位置と一致）: 精妙1・貫珠0。
- その1題（精妙六十二 `四三角成`）も、もう一方の読み `3四` が実際の成り先で説明できる。

したがって列頭の2字は**成り先**を指すのが原則で、九十七番だけが例外（原典の字か、
こちらの読みのどちらかが誤り）。盤面は2モデル完全一致なので採用し、初手は未決のまま残した。

## 駒数による違反検出（2026-11-25）

将棋の駒は1組しかない（歩18・香4・桂4・銀4・金4・角2・飛2・玉2）。成駒は元の種で数え、
持駒も含める。したがって**上限を超える盤面は、モデルが何個一致していても誤り**である。
`tools/material_audit.py` がこれを検査する。

```
python tools/material_audit.py          # 両コレクション
python tools/material_audit.py --md
```

検出結果:

| コレクション | 題 | `?` | 超過 |
|---|---|---|---|
| 貫珠 | 八 | 0 | ~~金 6~~ 訂正済み（全=成銀） |
| 貫珠 | 三十 | 1 | 金 5 |
| 貫珠 | 五十 | 1 | 金 5 |
| 精妙 | 九十六 | ~~5~~ 3 | ~~金 5~~ 訂正済み |

**貫珠八番は `?`=0 の完成盤面で金が6枚**あり、複数モデルの一致と初手検証を通過していても
誤りである。金1枚が別の駒（香・銀など）の読み違いだと確定できる。これは
「一致＝正しい」ではないことを示す、初の機械的な反例である。

四題とも金の過剰なので、疑うべきは金の字（あるいは金と紛らわしい香・銀）。原本で
金の升を確認すれば直る見込みが高い。`docs/open-issues.json` に記録した。

### 貫珠八番の追跡（持駒を原寸確認）

上限超過4題のうち、貫珠八番は `?`=0 の完成盤面なので、どこが誤りかを絞り込んだ。

- 盤下の持駒を 1400px で読むと **飛金金桂**（飛1・金2・桂1）で、記録と一致した。
- 盤上の先手金は 1一 と 7五 の2枚。持駒2＋盤上2＝4で、すでに上限。
- よって**後手の金 1三・5四 は金ではない**。この2升が誤りと確定した（銀・香などの候補）。

「持駒を先に確定させると、盤上のどの駒が誤りかが絞れる」という手順は他の3題にも使える。

### 決着: 貫珠八番の「金」は 全（成銀）だった

持駒を確定したうえで盤面の金の升を原寸で見ると、1一 と 1三 の字は **全** であった。
将棋の略字で **全 = 成銀**（銀の成駒）であり、金ではない。モデルは 全 を 金 と読んでいた。

- 1一 = 先手の成銀 (+S)、1三 = 後手の成銀 (+s) に訂正。
- 金は「5四の後手金・7五の先手金・持駒2」で**ちょうど4枚**。駒数違反が解消。
- 玉に王手は掛からず（1一の成銀は2三玉に届かない）、初手 四二金 (G*24) も王手のまま。

**教訓**: `全` は `金` と紛らわしく、モデルは金に寄せる。金が多い盤面はまず 全（成銀）を疑う。
同様に `と`(成歩)・`圭`(成桂)・`杏`(成香) も、成っていない駒との混同に注意する。

### 精妙九十六番: 成駒の略字をまとめて訂正

同じ手法（持駒→駒数→原寸）で、1段目を読み直すと4枚が成駒の略字だった。

| 升 | 旧 | 新 | 字 |
|---|---|---|---|
| 6一 | G | +s（後手成銀） | 全 |
| 4一 | ? | +R（先手龍） | 龍 |
| 3一 | ? | +P（先手と） | と |
| 2一 | l | +l（後手成香） | 杏 |

訂正後: 金は4枚ちょうど、先手の王手なし、`?` は 5→3。
そして**列頭 一六龍 が 4一→6一 の龍の手として王手**（`+R61<-41`）になり、初手も確定した。
成駒の略字（全・杏・圭・と）を素の駒として読むと、駒数・利き・初手のすべてが狂う。

## 死に駒の検査（2026-11-25）

成駒を素の駒と読み違えると、**動けない升に素の駒が残る**ことがある。次はすべて反則:

- 先手の歩・香が1段目、後手の歩・香が9段目
- 先手の桂が1〜2段目、後手の桂が8〜9段目

`tools/material_audit.py` の `dead_pieces()` がこれを検出し、`adopt_board.py` は
該当する SFEN の採用を拒否する。全150題の走査では **精妙七十五番** の 6九 の後手香
（香のままでは一度も動けない）が該当した。`+l`（成香）に直しても合法な王手は現れないため、
この題は盤面全体の再読が必要（`docs/open-issues.json`）。

成駒の略字（全・圭・杏・と）を素の駒として読む誤りは、
**駒数（金が増える）→ 死に駒（動けない升に残る）→ 利き（成駒の動き）** の3方向で検出できる。

### 二歩の裁定を試みた結果（2026-11-25）

二歩の2枚のうち片方をと金に変えて、ソルバーで詰みを比べた。

| 題 | 変換A | 変換B | 判定 |
|---|---|---|---|
| 貫珠 二十二 | MATE 3手 | MATE 3手 | **どちらでも同じ3手詰** |
| 貫珠 三十八 | 詰みなし（7手・厳密） | 詰みなし（7手・厳密） | 区別できない |

二十二番は二歩の升（9筋）が**解の手順に無関係**なので、どちらに直しても同じ3手詰になる。
盤面としては合法化できるが、どちらが正しいかは字形でしか決まらない。
三十八番はどちらでも詰まないので、盤面の別の所が誤り。

「違反升が解に無関係なら、ソルバーは裁定できない」— これは材料（駒数）の裁定との違いである。

## 唯一の王手で初手が決まる題（2026-11-25 再走査）

盤面を完成させた後、列頭が着手不能な題を再走査した。合法な王手が**ちょうど1手**で、
その着手元・経路・着地点が `?` に触れない（= `?` が何であっても成立する）題は、初手が確定する。

| 題 | `?` | 唯一の王手 | 印字列頭 | 扱い |
|---|---|---|---|---|
| 精妙 七十三 | 3 | 二五銀（1四→2五） | 六二馬 | 初手に採用、列は未割当 |
| 貫珠 十七 | 1 | 八二角成（9三→8二） | 四八桂 | 初手に採用、列は未割当 |

いずれも印字列頭は盤上・持駒に移動元が無い。`?` が任意でも成立する王手なので、
「他の王手が `?` に隠れている」可能性は残るが、詰将棋の初手は王手である以上、
この1手が最も確からしい。四十二・九・四十八番と同じ判断基準。

## 「動かせる升が1つ」でも採用しなかった例（2026-11-25）

## 3モデル目で割れを解消する（2026-11-25）

2モデル (Opus/Codex) が対立した升に、**3つ目のモデル (Claude Sonnet)** を同じ頁・同じ

| 1四 | 駒なし | +p（後手と金） | **+p** | 2票で +p を採用 |
| 4八 | g（金） | l（香） | **p（歩）** | 3者3様、保留 |

3者3様の 4八 は、多数決が使えないので保留した。**「3モデルで割れたら保留」** が原則で、

### 3モデル目の限界: 持駒を捏造することがある（2026-11-25）

精妙二番で Sonnet を4票目として走らせたところ、1九 を「駒なし」とし、さらに**盤下に無い持駒
（銀・歩）を報告した**。盤面の升だけを聞いたプロンプトでも、持駒欄を「読んだ」と錯覚して
値を埋めることがある。

したがって第3・第4のモデルは:

- **持駒は必ず原寸で別確認**する（モデルの申告を信用しない）。
- 1升だけの判定に使うときも、その頁の他の升が既知の値と一致することを確認してから票を数える。

精妙二番の 1九 は p / +b / +R / なし の4者4様で、多数決は成立しない（`?` 維持）。

### 3モデル目を使うときの手順（2026-11-25）

1. **左右を合わせる**: 盤面は `source.page` の「右」「左」と一致させる。左盤を読ませて
   右盤の題に票を入れると、**別の題の盤面**を読むことになる（実際に精妙二番でこれをやり、
   隣の三番を読んでいた。票は捨てた）。
2. **持駒を突合**: モデルの申告した持駒が draft と一致するか確認する。一致しなければ
   その読みは捨てる（Sonnet は精妙二番で存在しない持駒を作った）。
3. **既知の升を突合**: 玉の位置と、争点以外の升が draft と合うか確認する。
4. **争点の票を数える**: 2対1 なら採用、3者3様なら保留。

精妙六番の 9二 は 銀/飛/金 の3者3様で保留。精妙三番の 3一 は +r が2票（既存1＋Sonnet）で採用した。

### 第3モデルの実績（2026-11-25 時点）

| 題 | 争点 | 票 | 結果 |
|---|---|---|---|
| 精妙 三 | 3一 | +r（既存1＋Sonnet） | **採用**（2票） |
| 精妙 二 | 1九 | p / +b / +R / なし | 保留（4者4様） |
| 精妙 六 | 9二 | 銀 / 飛 / 金 | 保留（3者3様） |
| 精妙 八 | 4四 | 金 / 龍 / 成銀 | 保留（3者3様） |
| 精妙 十 | 8九 | と / 金 / 歩 | 保留（3者3様） |

5題中、決まったのは1題だけ。**Sonnet は既存2票のどちらかと一致するより、第3の答えを出す
ことが多い**（4回中3回）。字形が本当に曖昧な升では、モデルを増やしても決まらない。

一方、Sonnet の読みは持駒・玉・既知の升がほぼ一致しており（10/11, 14/15 升）、
**読みの質は高いが争点だけが読めない**という状態。これは人間の目でも難しい升である可能性が
高く、原本の高精細画像か別の頁（同じ題の別の図）が必要。

### 争点の升は「解像度の限界」にある（2026-11-25）

精妙六番の 9二（銀/飛/金で3者3様）を、頁の 10%（横1200px）で切り出して目視した。

- 同じ段の既知の升（9一桂・8一桂・6一飛・8二玉・7二角）は**はっきり読める**。
- 9二 の字だけが崩れており、**銀（金＋艮）とも飛とも言い切れない**。ループ状の崩しで、
  金の草書か と のようにも見える。
- 同じ頁の 4二 の と（既知）と比べても、線の数が合わない。

原因は解像度: NDL の原画像はこのコマで約2000px幅、1升あたり約100×130px。争点の升は
その中で最も崩れた字で、**これ以上拡大しても情報は増えない**（補間で滑らかになるだけ）。

したがって、この種の升は:

1. 原本（紙）を見る、または
2. NDL により高解像度のコマがあればそれを使う、または
3. 同じ題の別の図（本編と詰手で盤面が再掲されている場合）と突き合わせる

のいずれかが必要。モデルを増やす・拡大するでは解決しない。

### 盤面の升は「詰手の列の 同X」で確定できる（2026-11-25・精妙六番）

9二 の字は4モデルで 銀 / 飛 / 金 / と に割れ、字形からは決まらなかった。
決めたのは**その題の詰手列**である。

- PID:861217 R0000003左 の六番列は「三九銀打・同金・三七金・同桂・一八角成…」で始まる。
- 2手目 同金 は、9三に打った銀を**金**で取る手。後手の金は9四にあり、9三へ届く金は
  9二しかない（8三は原寸で歩と確認）。→ **9二 = 後手金**。
- 盤面再生で 1〜5手がすべて成立（先手の各手が王手、5手目で後手の合法手なし＝詰み）。
- 詰み証明器も同じ盤面で5手詰を独立に発見し、7手探索では 銀打93（＝列頭）も強制手に入る。
  つまり盤面・列頭・列の先頭5手が三者で一致する。

**一般則**: 升の字が読めないときは、その題の詰手列の「同X」を探す。X が盤上のどこから
その升へ届くかは、多くの場合ひとつに決まる。字形（モデルの票）より強い証拠になる。

**この事例の留保**: 列は 角成 の後も「同龍…」と続くが、この盤面では5手で詰むので
続かない。後半は変化手順か、隣の題の列の混在とみられる（`docs/open-issues.json`
seimyo-006）。列の途中までを採用し、後半は採用しない、という切り分けをした。

### 傾いた頁は「墨の塊の重心」から升を取る（2026-11-25・貫珠五十番）

罫線の自動検出は、傾いた頁（貫珠五十番）で1升ぶんずれた。そこで:

1. 頁の領域を取り、インクの連結成分（墨の塊）を出す（scipy.ndimage.label）。
2. 塊の重心を既知の升に割り当てる。既知の駒（例: 7四の香）で較正を検算する。
3. 読みたい升の**重心を中心に** ±2〜3% を切り出す。罫線に頼らないので、傾きの影響を受けない。

この方法で貫珠五十番の3段目を読み直し、3升の誤りを訂正した:

| 升 | 旧 | 新 | 根拠 |
|---|---|---|---|
| 8三 | +N（圭） | **+P（と）** | 字が小さく幅広の と |
| 7三 | P（歩） | **N（桂）** | 木＋圭。同筋4段目の 香（既知）で列を検算 |
| 6三 | 空 | **P（歩）** | 明瞭な 歩 |

7三が桂になったことで**7筋の二歩が解消**。さらに 2二 の字は金ではなく、材数から
**杏（成香）** と確定（龍にすると後手飛が2枚になり不可能。杏なら 香4・金4・桂4・銀4 が揃う）。
結果、貫珠五十番の規則違反（二歩＋金5）は両方消えた。

**教訓**: 罫線検出より墨の塊の方が頑健。ただし罫線に触れた字は塊が巨大成分に融合して
消えるので、既知の駒で較正を検算し、取りこぼしを疑うこと。

### 規則違反が「本の側」にある例（2026-11-25・貫珠三十番）

貫珠三十番は金が5枚（正規は4枚）で、長く違反として残っていた。5枚の升
（6四＝列頭の着手元、4七・5四・6七・8九＝後手）を墨の重心から原寸で切り出して1枚ずつ見た結果:

- **5枚とも 金**（人＋王＋2点）。成銀（全）・成香（杏）・成桂（圭）ではない。
- したがってこれは転記ミスではなく、**図そのものが金5枚**。

規則違反は「転記が怪しい」という警告であって、必ずしも転記の誤りではない。
字形が明確で材数だけが合わない場合、盤面を「合うように」書き換えるのは証拠の捏造になる。
この題は盤面を変えず、open-issues kanju-030-material に「原本で確認」として残した。

対照例: 精妙七十五番の 6九 は 香 と転記されていたが、字は **金**（人＋王）で、
香なら9段目の死に駒、成銀なら銀5枚で過剰、金だけが無違反。こちらは転記の誤りで、
盤面を直した（違反が消えた）。

### この本の 金 は2種類ある（2026-11-25）

精妙下巻の 金 は、標準体（人＋王＋2点。例: 七十一番3二）と**草書体**の2通りで刷られている。
草書の 金 は「左に箱状のループ・右に縦＋鉤」の形で、**そのままでは他の駒に見える**。

決め手は「同じ本の、証明済みの升と字形を直接比べる」こと:

- 精妙六番 9二 の草書字は、詰手列の 同金 で**後手金と証明済み**。
- 精妙九番 3二 の草書字は、その 9二 と**同じ向きで同一の字形**だった → 後手金と確定（q 4→3）。
- 一方、七十一番3二 の 金 は標準体で、草書字とは全く違う。

**副産物**: 草書字は向き（180度回すか否か）も同じなら同じ側。向きが違えば側が違う。
この照合で「草書の 金」を量産できる。

ただし**草書でも 金 と 銀 は別物**: 精妙八番 7四 の草書字は、証明済みの草書 金 と
右半分の形が違う（金は短い鉤、この字は長いループ）。銀・馬・龍のいずれかで、未決。

### 自動照合（画像相関）は判別力が足りない（2026-11-25）

草書の升を「証明済みの参照字形」と自動照合する試み（墨の塊を切り出し→64x64に正規化→
相関、0度/180度の両方を試す）を実装して測った。

- 正解（精妙六番9二の草書金）と 精妙八番7四 の未知字: **0.65**。
- しかし誤候補も **0.57〜0.64**（草書龍・と金）で、上位2件が接戦。
- 側（0度/180度）も、正解の側で必ずしも最大にならない。

**結論**: 墨の分布だけの相関では、崩し字の1字種を選び分けられない。字形の同定は
「並べて目で見る」方がまだ確実で、自動化するなら文字認識（モデル）側の改善が要る。
この試みは打ち切る（記録として残す）。

### 「升に駒があるか」の自動判定も失敗した（2026-11-25）

盤面の食い違いを自動検出するため、升ごとのインク量で「駒がある/空」を判定する
ツールを書いて試した（平均インク・中央領域・ぼかし最大値の3通り）。

- 正解と分かっている盤面（精妙九番・升ごとに原寸で確認し、9手詰まで証明済み）で

- しきい値を盤面ごとに自動決定しても、分布が二峰性にならないため分離できない。

したがって盤面の検証は、`tools/board_fit.py` で罫線を当てたうえで**1升ずつ目で見る**

この試みは打ち切る（misleading なツールを残さないため、実装は削除した）。

### 逆さの 杏 を 歩 と読み違える（2026-11-25・貫珠四十七番）

後手の 杏（成香）は 180度回すと「口が上・木が下」になる。これは**逆さの 歩**（止が上・少が下）
と非常によく似ており、実際に何度も 歩 と読んだ。

- 貫珠四十七番の 1一・6二 は 歩 と読むと 1八 の歩と二歩になり、材数でも香が合わない。
  杏（後手の成香）なら 香4枚で整合し、二歩も消える。
- 見分け方: 口（箱）が上なら 杏、箱が無く斜めの払いがあれば 歩。
- **規則が決める**: 歩と読んで二歩・材数超過になるなら、まず成香・成桂を疑う。

同じ混乱は貫珠三十八番（2五）・五十番（2二）でも起きており、いずれも 杏 が正解だった。

### 「規則で候補を絞る」走査の使い方（2026-11-25）

各 `?` に全22種（成/生 × 先後）を入れて、材数・二歩・死に駒・介在王手のどれも
増やさない候補を列挙する走査を回した（`?` が1つの盤面が対象）。

- ほとんどの盤面では候補が10〜20種残り、決定打にならない。
- しかし**材数が上限に達している盤面では強く絞れる**:
  - 貫珠五十番 4八 → 飛・龍・玉 の3種だけ（金銀香桂角はすべて上限）。
  - 精妙二番 1九 → 後手の生歩(p)は材数で不可（4モデルの1票が消える）。
  - 精妙十番 8九 → 生歩は不可（と/金は可）。
- 使い方: 先に走査で候補を絞り、その候補の中から字形で選ぶ。全候補を字形だけで
  見るより誤りが減る。

### 候補走査の落とし穴と、図の大きさの違い（2026-11-25）

規則で候補を絞る走査には2つ注意点がある。

1. **「空升」を候補に入れ忘れる**。走査は「その升に駒を置く」前提なので、実際に空だった
   場合を候補に数えていない。貫珠五十番 4八 は走査では「飛・龍・玉のいずれか」に絞れたが、
   原寸では**空升**だった（精妙十八・三十四の `?` も同様）。走査の結果は
   「置くなら何か」であって「必ず何か置く」ではない。
2. **図の大きさが頁ごとに違う**。罫線の間隔は 3.2〜3.6% の頁が多いが、貫珠十三番のように
   1.75% の小さな図もある。走査窓を固定すると半分の周期（高調波）を拾って
   「一致14本」のような過大な一致数になるので、**一致数だけでなく升の幅を目で確かめる**
   （小さすぎる/大きすぎる升幅は高調波を疑う）。

どちらの発見も、`tools/cellsheet.py` の1枚のシートで升が升として写っているかを見れば
判別できる。

### 複数 ? の盤面を部分採用するときの手順（2026-11-25）

1枚のシートで複数の升を読んだあと、その一部だけを採用する場合の注意。

- 採用する升だけを置き換え、**残りの ? はそのまま残す**。
- 検証は parse_sfen(sfen.replace("?", "1")) で行う（? のままでは
  parse_sfen が「bad piece letter」で落ちる）。これを忘れると、正しい升まで
  「違反」と判定されて全滅する（実際にこのバグで1回空振りした）。
- 材数・二歩・死に駒・介在王手の検査は、? を含む文字列のままでも
  material_audit が扱える。

### 1升だけ残った盤面はバッチに向かない（2026-11-25）

### 帯切出の限界（2026-11-25）

### 格子の最小二乗リファインは外れ値に弱い（2026-11-25）

罫線の当てはめが半升ずれる頁のために、既知の駒の**墨の重心**に格子を合わせる
最小二乗リファインを試した（重心 x = A + B·筋 → dx=B, x0=A−B/2）。

- 1回目の反復では 21/21 の駒が升に入り、重心も取れる（升の墨 2916〜6382）。
- しかし**2回目以降で発散**する。理由は2つ:
  1. 升の中の墨には罫線や隣の升の駒が混ざり、重心が外れる（外れ値）。
  2. 駒のある段が6段しかない頁では、段方向の回帰がほぼ決まらない
     （実測で dy が負になった）。
- 外れ値除去（残差の上位20%を捨てる）や「悪化したら戻す」を入れないと実用にならない。

**結論**: この方法は実装を続ける価値はあるが、単純な最小二乗では使えない。
升ごとの手読み（`tools/cellsheet.py` と帯切出）を当面の主力とする。

### 龍と馬は字形で区別できる（2026-11-25、精妙五十五番の訂正）

成飛（龍）と成角（馬）は、どちらも「飛車・角の成駒」で、材数だけでは入れ替えが効く。
精妙五十五番の 9五 は当初、材数の都合で候補順に `+b`（馬）として採用していた。

700px で読み直すと、字は **上に立・右に月・下に三** の構成で **龍**。
馬は **目＋四点** で、この字に四点は無い。したがって `+r` に訂正した。

独立の裏づけ: 印字の列頭は 三九飛（9三へ飛）。9三 を王手で指せる駒は
9五 の駒だけで、4三の飛は 8三桂・7三銀 に遮られ、6一の角は 9三 に届かない。
馬（9五）では 9三 へ指せないが、龍なら 9四 を経て 9三 へ指せる。

**運用**:
- 成駒は「候補を順に試して最初に通ったもの」を採らない。**字を見て決める**。
  材数は候補の絞り込みにだけ使う。
- `adopt_board.apply` は既読升の書き換えを拒否する。訂正が必要なときは
  `rewrite=[(筋, 段)]` で**訂正する升を明示**する（黙って上書きできない）。

### 後手の駒は180度回転して描かれる（2026-11-25）

この本の盤面図は、**後手の駒を倒立**（180度回転）で描く。同じ駒の先手・後手を
並べると回転関係にあることが分かる:

- 精妙三十一番 5七 の桂（先手 N）は正立、2一 の桂（後手 n）は倒立。
- 精妙四十五番 9九 の香（先手 L）は正立（禾が上・日が下）、
  8一 の香（後手 +l）は倒立（日が上・禾が下）。
- 王のみは正立で描かれる（対称に近いため実害はない）。

**使い方**: 升の字が正立か倒立かで**側**が決まる。これまで「向きでは側を読めない」と
していたが誤りで、精妙六十六番の 7六 と 9三 はこの規則で側を確定できた
（7六 は 6六 と同じ倒立＝後手歩、9三 は 7四 と同じ倒立＝後手飛）。

### 香と成香は字形では区別できない（2026-11-25）

- 一方、先手の 9九（L）は 8一 の**180度回転**で、やはり同じ字。
- つまりこの本は 香／成香 を書き分けていない。draft の +l は字形ではなく
  別の判断（解・文脈）によるもの。

同じ符号を採る（内部一貫性を優先）。成香か香かが解に効く題は、原本の別情報

### と（成歩）だけは向きで側を読めない（2026-11-25）

漢字の駒は後手を180度回転して描く（上の節）。しかし **と は例外**で、同じ後手の と が
頁によって別の向きで書かれている:

- 精妙五十九番 9九（後手 +p）: 輪が上、尾が下。
- 貫珠四十一番 5一（後手 +p）: 尾が上、輪が下。

両者は180度の関係にすらなく、書き分けの規則が読み取れない。したがって **との升は
向きから側を決めない**。側は

1. 詰探索で判別する（盤面が詰む側が正しい。精妙59 4三 は +P でのみ7手で詰む）、
2. それが長手数で終わらなければ、`?` のまま原本に回す（貫珠41 7二 は9手で未決）。

**教訓**: 一見使える「向き」の規則でも、かな書きの成駒には適用できない。
2例で規則を作る前に、同種の駒を3例以上並べて確かめる。

## 字形の向き照合は自己対照で失敗する（2026-11-25）

  後手なら 180 度が最良になるはず。
- 対象: 精妙41 6三（先手龍か後手龍か未決）。

結果、**対照が一致しない**。既知の後手龍3つ × 参照5つの最良回転は
180/90/270/0 にばらけた（例: 75 は参照96で180、参照50で270、参照21で0）。
つまり同じ「龍」でも字形の変異が大きく、この粗い相関では向きを測れない。

**運用**: 字形の相関で側を決めてはいけない。側は (1) 列頭が要求する駒、
(2) 王手が成立するか、(3) 材数、の3つでしか絞れない。
精妙41 6三 は (1)(2)(3) すべてを満たすが、後手龍でも王手1手が残るため
なお決まらない（`docs/open-issues.json` の `seimyo-041-rook-side`）。

## 整列度で「格子が合っているか」を数値にする（2026-11-25）

インク照合の可否を勘で決めずに済むよう、**整列度**を定義した:

> 整列度 = draft が駒を置く升の平均インク − draft が空とする升の平均インク
> （内升のみ、`?` は除く）

実測:

| 頁の状態 | 整列度 |
|---|---|
| 格子が合う頁（列頭が指せる題で確認） | **0.25〜0.34** |
| 格子が合わない頁（棄却された20題） | **−0.05〜0.14** |
| 格子を±1升ずらして最良にした場合 | **最大 0.06** |

- したがって **0.15 未満は棄却**（`tools/board_ink_check.py` に組込み）。
- 1升ずらしても 0.06 までしか上がらないので、棄却の原因は「1升のずれ」ではなく
  **頁の傾き・歪み**。救うには四隅ワープ（`tools/board_quad_sheet.py`）が要る。

### 前回の集計の訂正

整列度を入れずに数えた前回は「不一致14・棄却20」だったが、その14題の多くは
**整列度が 0.15 未満**（精妙8 −0.04、12 0.00、14 0.08、18 0.03、30 −0.01、
38 −0.05）で、**格子が合っていないだけ**だった。整列度で絞ると:

| 判定 | 題数 |
|---|---|
| 一致（49/49） | 3（精妙41・53・75） |
| ほぼ一致（47〜48） | 4（貫珠38、精妙11・19・81） |
| 不一致 | 1（精妙66、整列度0.20） |
| 棄却 | 33 |

**運用**: 盤面の誤りを主張できるのは、整列度が 0.15 以上の題だけ。

### 整列度の下限を 0.22 にした（精妙66 の検討から）

精妙66 は整列度 0.20 で、内升の**空升がすべてインクを持つ**（14升）という
不自然な形だった。調べると:

- 2〜4段では draft が空とする升が**全部**インクあり（例 2段の f8・f6・f3・f2）。
  1つの駒の読み落としではなく、**段の罫線が升の中に入っている**形。
- 行境界を1段ぶん下へずらすと整列度は 0.20 → 0.03 に**悪化**するので、
  単純な1段ずれでもない。
- 検証済みで格子が合う頁の整列度は 0.25〜0.34。0.20 はその下。

したがって下限を **0.22** に上げ、精妙66 は「測れない」に移した。
結果、**格子が合う7題はすべて配置が印字と一致**し、
「インクが盤面の誤りを示した題」は**0**になった。
（66 の14升は証拠にならない。四隅ワープで読み直す対象。）

### 太い罫線は 22% の内側除外では消えない（精妙66）

精妙66 の「空升なのにインクがある」14升を原寸で見ると、**2二 も 8二 も白紙**
（罫線だけ）だった。つまり ink は駒ではなく**罫線**。この頁は罫線が太く、
升の22%を除外しても線が標本箱に入っていた。

- 除外を **30%** に広げると、検証済み頁の整列度は 0.30〜0.40 に上がり、
  精妙90 が新たに測れるようになった（49/49）。
- 精妙66 は整列度 0.22 のまま棄却。升ごとの値を見ると**1〜4段だけが一様に
  0.12〜0.24**、5〜9段は 0.00。上へ行くほど格子が圧縮されている（＝段の間隔が
  頁の遠近で変わる）ため。1升ずらしでも直らない。

### 線スナップによるワープは未採用

罫線 ten 本をそれぞれ「線に沿ったインク最大」でスナップし、交点で升を四角形として
標本する試作を書いた。精妙41（良好頁）は 0.27→0.30 と改善し 49/49 を保つが、
精妙66 は 0.20→0.22、精妙12 は 0.00→0.02 にとどまり、**床 0.22 に届かない**。
よって道具としては採用せず、棄却頁は四隅ワープ（手測り）か原本に回す。

## 1手詰スキャン: 盤面が「印字の初手より短い詰み」を持つ題（2026-11-25）

本の規則の証明器で全完成盤面を `--max-ply 1` で走査し、**1手で詰む盤面**を探した。
`tools/replay_line.py` で MATE を確認できたもの:

| 題 | 印字の列頭 | 1手詰の手 | 意味 |
|---|---|---|---|
| 精妙76 | 一七金 | 金打71 | **一致**（手順を complete として追加済み） |
| 精妙15 | 三一金（原寸で確認済み） | 桂26 | **不一致 → 盤面が誤り** |
| 貫珠40 | 五五金 | 銀打55 | 不一致（列頭か盤面か未決） |

**精妙15 は強い証拠**: 列頭 三一金 は頁の最も右の列で確認済み（他と混同しない）。
その盤面が 桂26 の1手詰を許すなら、作意より短い詰みが成立してしまい、**盤面が誤り**。
詰将棋では「作意より早い詰み」は禁手なので、この盤面は成立しない。

- 精妙9（金打21）と貫珠22（飛12）は証明器と `replay_line` の判定が割れたので保留。

**運用**: 完成盤面でも「1手詰が別に成立しないか」を定期的に走査する。
成立していれば、その題の盤面は（列頭が正しい限り）誤り。
