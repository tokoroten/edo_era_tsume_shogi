### 1.2 将棋無双の一次資料と注意点

- 七世名人・三代伊藤宗看（1706–1761）の献上図式。原書名「象戯図式」、享保19年（1734年）刊。
- 献上本原本に作者自筆の解答が付属していたことが、昭和40年代の内閣文庫調査で判明。献上本は不完全作（不詰）が多い。
- 享保版の各伝本間で図の異同があり、増刷時に版木修正されたと推定される。→ **「どれが正か」をデータとして記録する必要がある**（`original_position` / 版・伝本の区別）。
- 不完全作とされる番号（文献指摘・要原典確認）: 第5、6、8、31、37、40、57、63、64、65、79、92番
- 所蔵・デジタル調査（2026-09-17、NDLサーチSRU/OpenSearch実測）:
  - 享保19年（1734年）刊の原書（序題「象戯図式」）は宮城県図書館伊達文庫所蔵（伊達文庫目録2132、NDLサーチ書誌 R000000054-I040_52132）。
    同館目録上の代替資料存否は「無し」。
  - NDL所蔵の1970年復製本（NDLBibID:000001281469）は紙のみでインターネット公開のデジタルなし（OpenSearch実測）。
    NDLデジタルの代替所蔵『古図式全書』第7巻（PID:2526139）は館内限定（`collections/edo/musou/collection.json` に記録済み）。
  - よって無双原典画像のNDLインターネット公開なしは確定。原典照合には館内利用・遠隔複写等の別手段が必要（未実施）。

## 3. SFEN / USI 表現の定義（詰将棋用）

- 仕様根拠: The Universal Shogi Interface http://hgm.nubati.net/usi.html （取得日 2026-09-15）
  - SFEN = 盤面部（9段を `/` 区切り、第1段＝後手陣1段目から）＋手番（`b`/`w`）＋持駒＋手数
  - 持駒順序: 飛角金銀桂香歩（RBG SNL P）の順、先手大文字→後手小文字。なしは `-`
  - USI指し手: 通常手 `7g7f`＋成 `+`、打 `P*3d`。段は a=1段 … i=9段
- 本プロジェクトの詰将棋SFEN規約（`docs/methodology.md` にも記載）:
  - 手番は常に `b`（攻方＝先手番）で記録する
  - 持駒欄は **攻方持駒（大文字）＋玉方持駒（小文字、駒箱＝残り駒）の両方** を記録する（USI仕様順序準拠）。玉方持駒が不明な場合は `-` とし `notes` に明記する
  - 玉方の持駒＝駒箱（盤上＋攻方持駒以外の全駒）という詰将棋ルールを採用し、検証器で自動算出・照合する
  - 手数は `1`（初手局面）で記録する
  - canonical solutionは **USI指し手の配列** とし、人間可読（日本語KIF風）表記はそこから自動生成する

## 4. 解答表現

- canonical: USI move list（例: `["5d5d", ...]` ではなく `["7g7f", ...]` 形式）。機械処理・検証器の入力になる
- 派生表示: 日本語表記（`▲５四銀打` 等）は `tools/` の変換器でUSIから自動生成する（手動転記しない）
- KIFファイルもUSI/SFENから自動生成し、GitHub Pagesで配布する

## 5. 自動検証の方針と既存solver調査

### 5.1 本プロジェクトの検証器（`tools/validate.py`、MIT、依存なし）

- JSON Schema相当のフィールド検査（標準ライブラリのみで実装）
- SFENパース、駒数検査（駒種ごとの総数上限、玉の数）
- 二歩・行き所のない駒への打・不成/成の合法性を含む指し手合法性検査
- 最終局面の詰み判定（玉方合法手の完全生成＝王の移動・合駒・取合を含む）
- 手数・手番パリティ検査

### 5.2 既存OSS（将来の高度検証用、現時点では未組込）

- **tsshogi** https://github.com/sunfish-shogi/tsshogi （MIT、取得日 2026-09-15）: KIF/KI2/CSA/JKF/SFEN-USIの相互変換・合法手生成を持つTypeScriptライブラリ。将来のNode製検証器・Pagesビューアの第一候補
- **tanuki-tsume-shogi** https://github.com/tokuhirom/tanuki-tsume-shogi （取得日 2026-09-15）: Rust製詰将棋ソルバー（全幅探索＋df-pn）の実装例。余詰検出・最長抵抗検証の参考実装
- **Kifu for JS / json-kifu-format**: KIF/KI2/CSAパーサ（EBNFあり）。KIF読みの参考資料
- 現時点の到達点: 自前のPython検証器で「解答手順の合法性＋最終局面の詰み」までを自動検証。余詰（別解）・最長抵抗の完全検証は将来課題とし、`status.unique_solution_verified=false` で明示する

## 6. 現代ルールとの差（古典詰将棋の注意点）

- **余詰・不詰**: 無双・図巧ともに不完全作が指摘されている（無双は番号リストあり、図巧も後世の修正版が存在）。原典局面を勝手に修正せず、`original_position` と `corrected_position` を区別する（スキーマに `corrected_sfen` を用意）
- **駒余り**: 古典は駒余りを許容する作風もあるが、近代詰将棋ルールでは不完全。`features.excess_pieces` 等で機械的に記録する
- **打歩詰・二歩・行き所のない駒・持駒（駒箱）**: 検証器で検査する
- **版木修正・伝本異同**（無双）: 伝本ごとに局面が違う場合がある。`source.edition` / `source.copy` で区別できる設計にする
- **不成の表記**: 本プロジェクトのKIF自動生成では不成を明示する
