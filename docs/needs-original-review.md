## なぜ自動で進まなくなったか（2026-11-25 時点の結論）

盤面（861216/861191）と解の列（861217/861192）は、**両方とも読める**。しかし
**両者が食い違う題**が残り、どちらを直すべきかを決められない。

- 一致する題は検証済み（初手 108/150）。
- 食い違う題では、列の初手が盤面で王手にならない（未決 42）。
- 列を読んで盤面を直そうとすると、列の帰属（どの列がどの題か）が要る。
  題号は列の右にあると分かったが、頁によって列数・段組みが違い、1題ずつ確認が要る。
- 盤面を直そうとすると、列の初手が要る。循環している。

**この循環を切れるのは原本の高精細画像だけ**（活字の列と、盤面の駒の両方が
同じ精度で読める画像）。既に試して駄目だった自動手法:

- 盤面全体の±1筋シフト（42本すべて直らない）
- 成駒を1枚足す（24本は直るが、一意な候補は現物と合わない）
- 9〜13手の詰探索で側を決める（長手数の題では決まらない）
- 列頭を他の盤面に当てる（多くの盤面で成立し、判別力が無い）

## 計算だけで分かること（原寸が要らない診断・2026-11-25 追加）

原寸を見なくても、盤面の誤りを**検出**できる手段が3つある。いずれも「修正」はできない。

1. **1手詰スキャン** — 盤面が印字の初手と別の1手詰を許す題は、作意より短い詰みが
   成立するので盤面が誤り（精妙15・貫珠40・精妙9・貫珠22 が該当）。
2. **5手以内の唯一手** — 強制初手が1つに定まり、それが列頭と違えば、同じ理由で盤面が誤り
   （貫珠16・33・34・44、精妙10・85）。一致した4題（貫珠13、精妙9・67・76）は
   盤面・列頭・詰みが同時に裏づけられる。
3. **整列度** — draft の駒の升と空升のインク差。0.22未満は格子が合っておらず、
   照合の根拠にならない（`tools/board_ink_check.py`）。
4. **一人分の駒数** — 合計（歩18など）ではなく**一人ぶん**の上限（歩9・香4・桂4・銀4・
   金4・角2・飛2・玉1）を超える draft は、必ず読み違いを含む。
   `python tools/material_audit.py --per-side` が12件を挙げる（`docs/per-side-audit.md`）。

**できないこと**: 1枚足す/動かす候補は一意にならない（精妙10で66通り）。
盤面の修正は原寸の読みにしか戻せない。

### 貫珠50 は歩が19枚になってしまう（2026-11-26）

draft の歩は**先手13枚＋後手5枚＝18枚**で、すでに駒一式のすべてを使い切っている。
しかし 4八 はインク 0.37 で、原寸の字形は**輪＋尾の と**。そのまま足すと19枚で不可能。
また先手13枚は、一人の上限9枚を4枚超えている。

**経済的な修復**: 先手の `+P` 6枚のうち4枚を後手の `+p` にすると、先手9・後手9で
ちょうど上限に収まる。どの4枚かは、初手が王手になる向きと、周りの漢字駒の向きから
絞る。4八 は、この修復の後でも と なら19枚になるので、**飛/龍の読み違い**か、
隣の升の字が窓に入ったものとして、もう一度切る。

### 玉図51 は飛が4枚・9筋が二歩（2026-11-26）

`material_audit.py` を全コレクションに広げて最初に出た例。draft は
`9/2R2G+R2/PPPGR4/P1S1P4/1S7/1k7/S1+P?G4/G?SL+R4/3+P2L2` で、**飛が4枚**（上限2）
かつ**9三・9四 に先手の不成歩が2枚**（二歩）。どちらも成立しない。

- 原寸で切ると、`+R` の2升（2三・8五）は**横棒＋「3」形＋閉じた輪**の字で、
  同じ盤の と（7七・9六。鉤形）とも 飛（3五）とも違う。飛は合計2枚までなので、
  この2升は飛ではありえない。残る重い駒は**馬**で、形は精妙で「倒立した馬」と
  記録した字（點4つ→横棒、日→輪）と一致する。
- 向きは「輪が下・棒が上」＝**倒立**なので後手の馬（+b）と読めるが、この頁の
  天地は玉（8六）の向きでしか押さえていない。側は原本で確認してから直す。
- 9三 と 9四 は**別の字形の歩**（片方は止が上、片方は倒立）。二歩にならないためには
  片方が後手でなければならず、字形の差がそのまま側の差である可能性が高い。

この盤面はまだ「完成」にできない。修正は 2三・8五 の駒種（+R→馬）と、9三/9四 の
側の2点で、どちらも原寸の字を見れば決まる。
