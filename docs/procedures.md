## 2. 翻刻の手順と記録形式

1. IIIF で当該コマを取得（`/api/iiif/<PID>/<RID>/<x>,<y>,<w>,<h>/<w>,/0/default.jpg`）。
   1コマを左右頁に分割し、各頁を幅1500px程度に拡大して読む。
2. 目視を主とし、判読に迷う箇所は `codex exec -m gpt-6.1-terra -s read-only -i <jpg>` に
   **ASCII 限定の JSON 契約**で委託して突き合わせる（文字化け回避のため）。
3. 生データは `collections/<period>/<collection>/procedures/<leaf>.json` に保存する。
   - `transcription.method` に委託の有無、`verified` に人手照合の有無を必ず記す。
   - 駒コード: `K`玉 `R`飛 `B`角 `G`金 `S`銀 `N`桂 `L`香 `P`歩 `Q`と `X`杏 `Y`圭 `Z`全 `M`馬 `H`龍、`?`=不能。
   - 行き先: 半角2桁（筋→段、例 八八=`88`）、`同`=`same`。
   - 印: `+`=成、`=`=不成、`d`=打、`-`=なし。
4. **USI 化は盤面との整合検査を通った場合のみ**行う。
   - 対応する draft の SFEN に `?` が残る場合、その升を含む手は確定できないため
     `intended_solution_usi` には入れず、生データと `notes` に留める。
   - `?` が無い図のみ、手順の合法性・王手継続・最終形の詰みを
     `tsume-solver.exe`（probe / solve-sfen）で検証し、`solution_usi` を確定する。
5. 詰手の翻刻結果は draft の `intended_solution_source` に
   「NDL PID:861217 R0000002 右頁 初番」のように出典を書き、`intended_solution_usi` は
   USI 化できた場合のみ設定する。

### 3.8 初手検証の手順（2026-11-17）

詰手の初手を1題ずつ確定する手順。人手でも同じ手順で追試できる。

1. **対象の選択**: `python tools/list_first_move_targets.py --limit 25` で、未検証の題を **`?` の少ない順**に並べる（盤面 RID・原典記述付き）。毎回の出力は `docs/first-move-targets.md` に保存し、`TestFirstMoveTargets` が一致を検査する。
2. **玉位置**: 本編/上巻の draft の `sfen` から後手玉（`k`）の筋段を取る。
3. **列位置**: `docs/columns-kanju.md` / `columns-seimyo.md` の x範囲から候補列を選ぶ。**校正紙**: `python tools/column_sheet.py <pid> <rid>` で、検出した列に c1, c2, … の番号と%を描いた画像を出力できる。これで「c11 の列頭」のように列を指定でき、%の目測ずれを避けられる。
   **題簽の全文読取（2026-11-18）**: 題簽は縦に3〜4字で、`--region pct:<x>,25,5,28 --width 420` の縦長切出なら全文が読める。上部だけ（y 14-24%）を切ると先頭1字しか見えず、誤認の原因になる。
   題簽は列の右または左に置かれ、頁ごとに異なる。題簽自体も1列として検出される。
4. **葉ごとの対応確認**: `python tools/leaf_heads.py R0000015 --range 50 59` で、記録済みの列頭が**どの題の玉に王手になるか**を一覧で出せる。一つの列だけを王手にする題があれば、その組み合わせで帰属を決められる（例: R15 の「三三銀」は54番だけに王手）。
   **注意**: 一意性は「その葉の中」で判定する。全葉の列頭をまとめると同じ玉位置の題が多く、どの列も複数の題に王手になって一意性が失われる（2026-11-18 に確認）。
   `leaf_heads.py` は末尾に**題ごとの候補**（`UNIQUE` / `N heads` / `none`）と**conflicts**（同じ1候補が複数の題に付く）を出す。conflicts がある題は、どちらかの列がまだ記録されていないということ。
5. **隣題との切り分け**: `python tools/first_move_gaps.py` は、未検証題の玉に王手になり、かつ隣の題（前後1題）の玉には王手にならない列頭を列挙する。詰手の先手の手は必ず王手なので、この条件を満たす列はその題のものと決めやすい（例: 九十五番の「一四香」は九十四番の玉8五に王手にならず、九十五番の初手と確定）。帰属未決の列頭は行き先が未記録なので、**段→筋と筋→段の両方**を試し、王手になった読みを `raw→行き先` の形で出す（2026-11-20）。
6. **候補の列挙**: `python tools/guess_first_move.py kanju 14` で、その draft の玉に
   王手になる (駒, 升) の一覧を出す。読んだ小字が一覧に無ければ、玉位置か読みが誤り。
7. **切出**: `tools/iiif_crop.py` で列の上端（y 19〜29% 程度）を幅800で切り出す。
   小字が読めない場合は `tools/iiif_grid.py` で座標を確認して切り直す。
8. **読取**: 駒名の上の2字（行き先）と成/打の小字を読む。2字は斜めに組まれ、
   **段→筋が多いが題により筋→段**（十三番は段→筋、十四・十五番は筋→段）。
   順序は**王手の成立**で決める（`tools/guess_first_move.py` で候補を列挙）。
   readings JSON の `order` は raw が筋→段のとき `file-rank`。二/三の小字は判別しづらい。
9. **検証**: その駒を dest に置いた盤面で、**その駒自身が**玉を攻撃するかを確認する
   （`pseudo_targets` を使う。`is_attacked` は他の駒が既に利いている場合も真になるため、
   非合法な draft では誤検出する。`tools/guess_first_move.py` の `checks_from` と同じ計算）。
   王手にならなければ、列の帰属か読みが誤り。**王手になる解釈を採用する**。
   **開き王手（2026-11-20）**: 動かした駒自身が利かない場合でも、その駒が止めていた味方の利きが
   玉に通れば王手になる（五十九番: 飛5五が角3三の対角線3三-4四-5五-6六を止めており、飛が5三へ成ると
   角が開き王手）。検証は「動かす前は王手でない」「元の升を空けて移動先に置くと王手」の2条件
   （`tests/run_tests.py` の `first_move_checks`）。記録には `check: "discovered"` と
   `origin: {file, rank}` を付ける。`tools/guess_first_move.py` は直接王手の候補のあとに、
   動かすと王手になる味方の駒（開き王手の候補）も列挙する。
10. **記録**: `docs/kanju-first-moves.json` / `docs/seimyo-first-moves.json` に
   `{number, piece, promoted, file, rank, raw}` を追加し、テストで固定する。
   `board_q` と `confidence`（good/partial/sparse）を併記し、空升が多い盤面での
   「王手成立」を過信しない。`TestFirstMoveDigits` が raw の2字＝筋と段の集合、
   `TestFirstMovePieceNames` が駒名と SFEN 駒種・成の一致を検査する。
11. **機械検証できない読み**: 盤面が不完全で王手検証ができない題は、読めた手だけを
   `docs/kanju-procedure-readings.json` に `attacks_gote_king: true|false|null` で記録する。
   `TestKanjuProcedureReadings` が記法の極性（段が先）・手番順・「同」の升・王手の主張を
   検査する。矛盾が出たら読みを見直す（例: 十三番は 9二銀不成では9三の玉に利かず矛盾と
   なったが、駒名右の小さな「成」を見落としていたと判明し、9二銀成で解消）。

12. **盤面升の位置決め（2026-11-20）**: `python tools/board_grid.py <pid> <rid> --region pct:X,Y,W,H` で盤枠を検出し、罫線を等間隔近似した升境界（%）と 9×9 のインク量を出す。`--out` の注記画像で目視確認する。region に枠外の頁罫や題簽を含めると1列ずれるので、盤枠だけを含める。実例: 玉図八十八番は x 48.78-83.26 / y 34.45-74.72 で、升の列帰属が±1から確定に変わった。インク量は駒の有無の判定用で、種類・先後は原寸切出で読む。守方玉は本書では点なしの「王」で刷られるため、点の有無では先後を決めない（守方玉のみが出る詰図の原則を使う）。**盤面の向きは左頁と右頁で反転する**ので、読む前に向きを決める。実例: 玉図一番（861197 R6左）は画像左=f1（玉 f8 が画像の右寄り）、精妙八十番（861216 R46右）は画像左=f9（香 a-f9・玉 b-f9 が画像左端、飛 b-f2 が画像右寄り）。既知の玉位置と画像上の位置を突き合わせて向きを確定する。

**列の切れ目（2026-11-20 追記）**: 題簽の隣接列が初手列とは限らない。題簽から左へ順に見て、
**最初に王手になる列頭**を初手列とする。実例: 五十五番は題簽の左隣 c14「一九桂」が玉9二に王手に
ならず、次の c13「三九飛」が初手。八十一番も「二六角」が王手にならず「四四龍」が初手。
先手の手はすべて王手なので、王手になる列が複数あるときは題簽に最も近い列を採る。同じ列を
2題に割り当ててはいけない（七十八・八十番の重複で判明。玉位置が同じ題は王手判定で区別できない）。
題簽が葉の左端にある題は本文が次葉の右端に続く（七十八・八十五・五十九番）。

**盤面図の場所（2026-11-18）**: 盤面図は詰手とは別の PID（貫珠は 861191）にあり、
詰手のコマ番号（861192 R3〜R18）とは対応しない。盤面の圖は各 draft の `source.page`
（例: 十三番は 861191 R0000011左）を見る。861191 の RID は**見開き**で、右頁が先の題、
左頁が後の題（十二番=右、十三番=左）。持駒は盤枠の**上と下**に印刷され、枠内の駒と
混同しない。盤面の駒の向き（先後）は版によって判別できないことがあり、詰手と矛盾する
場合は詰手を優先して色を決める（例: 十三番 9三の桂は2手目「三九玉」で取られるので先手）。
注記: 列帰属は「題簽に隣接する列」かつ「その初手が王手になる」の2条件で決める。
一つの題が複数列に及ぶため、隣接列が王手にならない場合は同じ題の範囲で隣の列を
順に試す。王手が成立しない読みは誤りとして扱う。
**限界 3**: 列頭の駒が SFEN の玉を攻撃しない例が多く、**SFEN の玉位置そのものが誤っている
可能性**がある（玉位置は既に3件を訂正: 精妙22・74、貫珠45）。初手検証の前に、盤面図で
玉の位置を原寸確認することが前提になる。玉位置が正しいと確認できた問題でのみ、王手の
不成立を「列帰属の誤り」と解釈できる。
**限界 2**: 盤面が玉だけ・ほぼ空の draft（例: 貫珠001 は 4k4/9/... b RBGSN 1）では、
空盤を挟んで任意の利きが成立するため王手検証が無意味になる。この場合は検証せず未検証とする。
**限界**: 機械検証は「その駒を置けば王手になるか」だけを見ており、列の帰属そのものは
検証しない。王手になる中盤手を初手と誤認する可能性があるため、記録は
docs/first-move-status.md で「検証済み」としつつ、人手の追試を歓迎する。

### 3.11 途中局面の検証に使える／使えないツール（2026-11-25）

- **使える**: 初形（先手番）の詰み証明・初手の列挙 — `tsume-solver solve-sfen <SFEN> --max-ply N`。
  例: 貫珠六番の4手目までの局面（先手番）は MATE distance 3 で、5手目 L*5f が詰み手の一つ。
- **使えない**: **後手番の途中局面**。SFEN の持駒欄は「手番側の持駒」しか表せないため、
  後手番にすると先手の持駒（金香など）が失われ、局面が別物になる。
  実際に 5手目 L*5f 後の局面を `w` で渡すと「持駒 G」が後手のものと解釈され REFUTED になった。
- 途中局面の詰み証明は、両者の持駒を保持できるエンジン（やねうら王等）か、
  人手の再生で行う。原典の手順翻刻では「各手が合法で王手になっているか」を
  盤面再生で確認するだけでも十分な検証になる。

### 3.12 貫珠六番: 読んだ5手は「5手詰」で終わる（ソルバーの7手との差）

読んだ5手（一六銀・六三王・二六角成・四五王・六五香打）を盤面再生すると、
**5手目で後手に合法手が無い**（28種の候補手すべてが王手を外せない）＝ 5手詰で終わる。

一方ソルバーは初形で **distance 7**（最善の受けを選ぶと7手）と返す。したがって
原典のこの列は「最善応手の one line ではない」か、2手目の読み（六三王）が
実際は別の手（同玉 など）である可能性がある。

- 5手が合法で王手を続けることは確認済み（誤読ではない）。
- ソルバーの最善線は 1…同玉（5b6a）で7手。原典は 1…六三王（5b6c）と受けている。
  つまり原典の列は**後手が別の受けを選んだ変化手順**で、詰みであることに変わりはない。
  （詰手の本は最善応手とは限らない一本の手順を載せることがある）
- 列の続きに読めた「同・三六打・五五王・六六銀」は、5手目で詰んでいる以上、
  **隣の題（七番）の列**である可能性が高い。
- 結論: 六番の手順は **5手（一六銀・六三王・二六角成・四五王・六五香打）で詰み**。
  最善応手を尽くした場合の7手筋は別途（ソルバー）。

### 3.14 手順翻刻の実用手順（2026-11-25 まとめ）

1. **列の特定**: 題簽の位置から、その題の最初の列を決める（`tools/build_procedures_page.py` の
   葉対応と、`kanju/seimyo-column-heads.json` の x% を使う）。
2. **列の切出**: `python tools/iiif_crop.py --pid <PID> --rid <RID> --region pct:X,Y,W,H --width 700`。
   1回で縦 20〜25% ずつ、上から順に読む（1枚に詰めると解像度が落ちる）。
3. **1手ずつ読む**: 小字2字＋駒種＋（成/打/同）。小字の順は**段→筋**が基本だが題によって揺れる。
   迷ったら両方の読みをメモに残す。
4. **盤面再生で検証**: 先手の手は「王手になっているか」、後手の手は「王手を外しているか」を
   `tools/validate.py` の `is_attacked` / `pseudo_targets` で確認する。
   合法でない手が出たら、その手の小字を読み直す（盤面を疑うのは最後）。
5. **詰みの確認**: 最後の手の後で後手の合法手が0なら詰み。詰まなければ、どこかの手が違う。
6. **ソルバーの使いどころ**:
   - 初形（先手番）の詰み証明と初手の列挙 → `tsume-solver solve-sfen`。
   - 途中局面は**後手番だと持駒が落ちる**ので使えない（§3.11）。自前の列挙で代替する。
7. **記録**: 完走した列だけ `collections/<...>/procedures/<題>.json` に
   `moves`（col/n/piece/dest/marker）で書く。`verified` は人手照合まで false。
   途中までの読みは本ドキュメントに残す（`kanju-procedure-readings.json` は初手未確定題専用）。

この手順で 貫珠六番（5手）は完了、三十四番は3手まで検証済み（§3.10〜3.13）。

### 3.19 参考: 詰みの規則が2つある


このプロジェクトには**詰みの定義が2つ**あり、両者は別物である。混同すると
「ソルバーは詰まないと言うが本の手順は詰む」という矛盾が起きる。

| 規則 | 後手が打てる駒 | 使う道具 | 用途 |
|---|---|---|---|
| **本の規則**（持駒のみ） | 持駒だけ | `replay_line.strict_mate` / `tools/mate_lines.py` | 江戸の本の手順を読む・検証する |
| **データセットの規則**（駒箱） | 盤上・持駒以外の**未使用の全駒** | `validate.is_mate` / `tsume-solver` | 提出レコードの詰み保証 |

実例（貫珠六番の本の5手を並べた最終局面）:

- 後手の持駒: 空
- 後手の駒箱: 歩15・香2・桂1・金3・角1・飛2
- `strict_mate`（本の規則）= **詰み**
- `validate.is_mate`（駒箱）= **詰みではない**（歩を打って延命できる）

したがって:

- `tsume-solver` の REFUTED は「**駒箱規則で**詰まない」の意味であり、本の手順が
  間違いという意味ではない。
- 本の手順の可否は `replay_line` / `mate_lines`（持駒のみ）で判定する。
- データセットの `solution_verified` は駒箱規則で主張しているので、両方を明記する。

この区別により、以前「矛盾」と見えた次の結果は説明がつく:

- 貫珠六番: 本の5手は持駒規則で詰み、駒箱規則では7手必要（ソルバーの MATE 7）。
- 精妙四番: 持駒規則では7手の強制詰みがある（`と73 玉71 馬61 玉61 角打43 玉51 圭52`）。
  駒箱規則では9手以内に詰みが無い（ソルバー REFUTED）。

### 3.21 升の字が読めないときは「同X」を探す（2026-11-25）

盤面の升の字形がモデルの票でも決まらないとき、**その題の詰手列**が最強の証拠になる。

1. 手順列を上から読み、初手（列頭）と一致する列を見つける。
2. 2手目以降の「同X」（直前の手の升を X が取る）を拾う。
3. 盤面上で「X がその升へ届く」経路が1つだけなら、**その升の駒種が X に確定**する。
4. さらに列の先頭数手を盤面再生し、先手の各手が王手・最終手が詰みになることを確認する。

実例（精妙 六番）: 列は 三九銀打・同金・三七金・同桂・一八角成。2手目 同金 により
9二=後手金、5手で詰み。字形は4モデルで割れていたが、列で一発で決まった。

注意: 列の後半が盤面と合わないことがある（変化手順・隣の題の混在）。合うところまでを
採用し、合わない部分は採用しない（docs/open-issues.json に残す）。

両書とも、解の頁は**右から左**に列が並び、題号はその列の**右隣**に縦書きされる。

- 貫珠 861192 R0000006: `十一番`（右）→ 列 → `十二番` → 列、と左へ。

### 小字の向きは頁ごとに検算する（2026-11-25）

行き先の小字は駒の**左上と右上**に分かれて置かれ、どちらが段でどちらが筋かは
頁によって一定しない（精妙33では 四 が左・一 が上、貫珠では上と右）。

**運用**: 各列の**初手**は列頭（`docs/*-first-moves.json`）で既に分かっているので、
その1手で「どちらの小字が段か」を検算してから、2手目以降を読む。
初手で向きが決まらない（同じ数字）場合は、2手目を盤面で再生して確かめる。

例: 精妙33 の初手は列頭 四一銀（1四）。列の小字は 四（左）・一（上）なので、
この頁では「左＝段・上＝筋」と決まる。
